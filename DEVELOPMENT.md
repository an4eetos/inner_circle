# Development

Monorepo: Go API + worker (`backend/`), Flutter app for iOS and Android (`mobile/`),
Next.js web (`web/`), shared HTTP contract (`api/openapi.yaml`), local stack (`infra/`).

## Prerequisites

| Tool | Version | Used for |
|---|---|---|
| Go | 1.27+ | backend (codegen tools are pinned in `backend/tools/go.mod`, no global installs) |
| Docker | recent | Postgres, S3 (SeaweedFS), Mailpit; Dart client generator; integration tests |
| Flutter | 3.44 (Dart 3.12) | mobile |
| Node | 22 | web |
| golangci-lint | v2 | backend lint |
| Xcode | latest | iOS builds only |

## First run

```bash
make setup      # .env from .env.example, git hooks, dependencies
make dev        # Postgres + S3 + Mailpit, migrations, API (:18080) and worker with hot reload
curl localhost:18080/v1/healthz
make web        # http://localhost:3000
make mobile-run FLAVOR=dev
```

Local ports are set in `.env` (API 18080, Postgres 55432, S3 58333, Mailpit UI 58025) so they
don't clash with other projects.

## Everyday commands

| Command | What it does |
|---|---|
| `make gen` | Regenerate everything from `api/openapi.yaml`, SQL queries, ARB strings and drift tables |
| `make test` | Go tests (incl. Postgres integration via testcontainers), Flutter tests, web typecheck + build |
| `make lint` / `make fmt` | Linters / formatters for all three apps |
| `make migration name=add_users` | New goose SQL migration in `backend/migrations` |
| `make migrate` / `migrate-down` / `migrate-status` | Apply / roll back / list migrations |
| `make infra-reset` | Wipe local volumes |

## Changing the API

1. Edit `api/openapi.yaml`.
2. `make gen`: Go strict server (`backend/internal/api`), Dart client (`mobile/packages/api_client`),
   TS types (`web/src/gen/api`).
3. Implement the new method on a module handler and embed it in `backend/internal/server/server.go`.

Generated code is committed. CI regenerates it and fails if the result differs.

Errors are RFC 9457 `application/problem+json` with a stable `code`. Add new fields and enum
values freely: clients ignore unknown fields and map unknown enum values to a fallback.

## Backend layout

```
backend/
  cmd/{api,worker,migrate}     binaries
  internal/platform/           config, db, logging (health-data scrubbing), httpx middleware, problem, telemetry
  internal/<module>/           one package per domain module (health today)
  internal/api/                generated by oapi-codegen
  migrations/                  goose SQL, embedded in the binaries
  queries/                     sqlc queries → internal/platform/db/... generated code
```

Configuration is environment variables only (see `.env.example` and
`backend/internal/platform/config`). `DB_AUTO_MIGRATE` is allowed only with `APP_ENV=local`;
deploys run `migrate up` as a separate step.

Logs never contain health content or credentials: the logger redacts sensitive keys
(`email`, `token`, `meds`, `meal`, `result`, `note`, `health_*`, …). Access logs record the route
pattern, never the raw path or query string.
